# GS1 door NPC on 1.39, 2.22 and 2.31, 2026-11-14 (issue #45)

This run checks the touch branch of a GS1 level NPC on the classic builds,
which the five-client rerun (`five-clients-2026-11-14.md`) could not show.

Loopback only. Everything ran in the Debian lab VM, inside a namespace
whose only interface is `lo` (checked before the clients started). The
clients ran under Wine, behind a logging relay. No public server and no
real account were used.

## Setup

- **Server:** `main` b827cd2, then the fix b64552d.
- **Clients:** 1.39 `GNW07080` (direct), 2.22 `GNW03014` and 2.31
  `GNW28015` (both through the lab listserver).
- **The NPC:** the door from seihai-core's `delivery` tests, written once
  with `door.gif`/`dooropen.gif` and once with the `.png` names. The art is
  32×32 with an 8-bit palette: the closed door is red, the open one green.

## Results

| Build | Door drawn | Touch runs the script |
|---|---|---|
| 2.22 | gif and png | **yes**, for both: it asked for `dooropen.*`, drew it with `opened`, closed again about 1 s later, and sent `PLI_NPCPROPS` each time |
| 2.31 | gif and png | **yes**, the same on screen. It sent no `PLI_NPCPROPS` all session |
| 1.39 | png on `main`; gif and png with b64552d | **no**, for either door |

On 1.39, `if (playerenters) { message entered; }` did run, so 1.39 runs
GS1 here, just not this script's touch branch. A plain
`if (playertouchsme)` and a version using flags did not fire either, and
the same level on GServer-v2 behaved the same way. Why 1.39's touch does
not fire is not settled, but it is not something this server sends
differently.

## Fixed: 1.39 asks for `setimg` images with no extension

1.39 asked for the gif door as `door`, with no extension. On `main` the
server answered `PLO_FILESENDFAILED`, so the door was never drawn and the
player walked through it. GServer-v2 answers such a request from a build
older than 2.1 with `door.gif`.

`files::wanted_name` (b64552d) now does the same for builds whose art is
`.gif`. The 1.39 exchange is:
- `PLI_WANTFILE "door"`;
- `PLO_FILE "door.gif"` with the GIF87a data;
- the log line `file door.gif: sent`.

1.39 then drew the gif door, and the door blocked the player. 2.22 was
unchanged.

## Other notes

- 2.x draws GIF palette index 0 as transparent but draws it in PNGs.
- 2.x sends `PLI_TRIGGERACTION` (38) `pushed,1` while pushing; it is
  logged once as not handled.
- There were no crashes and no disconnects.
