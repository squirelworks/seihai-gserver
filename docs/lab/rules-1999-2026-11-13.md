# The 1999 rules with real 1.3x clients, 2026-11-13 (issue #110)

Loopback only. Everything ran in a Debian lab VM, inside a private network
namespace whose only interface is `lo`, with the clients under Wine
(`tools/lab-wine.md`). No public server and no real player account were used.
This is a partial run: what passed is below, and so is what is left and why.

## Setup

- This server at `main` (`47d0cd5`), `cargo build --release`, run with
  `--verbose`, bound to 127.0.0.2:14812.
- A logging relay on 127.0.0.1:14812 decoded every message (the 1.x clients
  use zlib framing, gen 2).
- World:
  - `s110.nw`, the start level: all grass, with a link at x 34 into `h110.nw`.
  - `h110.nw`: a level NPC
    `if (playerenters && isleader) { puthorse ride.gif,40,30; }`, a hare
    (`BADDY 36 36 5`), tiles 2, 3 / 18, 19 at x 24–25, y 30–31 meant as a
    bush, and a link back at x 0.
  - `config/server.txt`: `respawn_time = 10`, `horse_lifetime = 10`,
    `baddy_respawn_time = 15`, `alignment_time = 30`, `create_accounts = true`.
- Clients: real 1.35 (`GNW13040`) and 1.39 (`GNW07080`), "One Player Online"
  to 127.0.0.1:14812. They were run twice: with `rules = v2`, then with
  `rules = 1999`.

### The horse, `rules = v2`

1.39 entered `h110.nw` first. It got `PLO_ISLEADER` (10), its client ran the
NPC's `puthorse`, and sent `PLI_HORSEADD` (7):

```
12:26:44.182  C>S 7  27 70 5c 23 72 69 64 65   x 40, y 30, dir 3, "ride"
```

The player was still walking right and got on the horse
(`PLI_HORSEDEL` (8) `28 70 5c`, then prop `ride`). It rode to x 61.5 and got
off there, which sent a second `PLI_HORSEADD`:

```
12:26:52.176  C>S 7  27 9b 5c 23 72 69 64 65   x 61.5, y 30
12:27:02.212  S>C 18 32 9b 5c                  PLO_HORSEDEL at x 61.5, y 30
```

The server told the level the horse was gone **10.04 s** after it was left,
as `horse_lifetime = 10` says.

### Why the rest was not reached

- **Timing under load.** The VM ran at a load average of 11 to 18 (other
  labs). The 1.x clients reacted to held keys late or not at all, so the
  sequences (second player arrives within 10 s, player-versus-player hits)
  did not line up.
- **`puthorse` under `rules = 1999`.** 1.35 entered `h110.nw` (from its
  cache, with a modification time) and was made leader, but its client sent
  no `PLI_HORSEADD`. In the v2 run, 1.39 entered with a fresh level and did
  send it. The likely cause is that `isleader` was not yet true when
  `playerenters` ran, rather than a server fault.
- **The bush.** Swinging at tiles 2, 3 / 18, 19 sent no `PLI_BOARDMODIFY` from
  1.35 or 2.22. They may not be a cuttable bush on these clients' tile sheets.
  The rerun should use bush tiles from a real 1.x level.
- **`toall`.** None of the 1.x client files says how a player sends `PLI_TOALL`.

## Other observations

  the account has `RUPEES 0`. Not explained.
