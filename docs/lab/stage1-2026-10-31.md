# Stage 1 lab run, 2026-10-31

Loopback only (`127.0.0.1`), in a cloud container. No public server, no real
player account, no real Graal client.

## Setup

- Server: this branch, `cargo build --release`, a throwaway world with
  `create_accounts = true` and `allowedversions.txt` = `*`.
- Client: Seihai `v0.0.3` (`8b9b07f`, the same `seihai-core` this
  crate pins), `seihai-mae` release build, headless under `xvfb-run`, one
  process per profile, each with its own `HOME`.
- Script: `tools/lab-matrix.sh target/../seihai-mae 60`.

## Before

The scaffold printed "not implemented yet" and exited; nothing could log in.

## After

All 46 Seihai profiles, 1.21 to 6.03r7 Linux, logged in at the same time,
printed `logged in to 127.0.0.1:14802` and `level from the server's board`,
and stayed connected until the script stopped them at 65 s (the server logged
each one leave at 65 s after its login). No client printed a panic, a closed
connection or a disconnect.

| generation | builds | result |
|---|---|---|
| gen 2 | 1.21, 1.28 beta 2, 1.3 test, 1.31 to 1.39 | 12 of 12 |
| gen 3 | 1.41, 1.42, 2.00 to 2.05, 2.1, 2.12 to 2.17 | 16 of 16 |
| gen 5 | 2.22, 2.3, 2.31, 3.04, 3.153, 4.04r2, 4.20r6, 4.20r8, 5.00r7, 5.12, 5.24r4, 5.30r3, 5.31r4, 6.00r2, 6.015, 6.034, 6.03r7, 6.03r7 Linux | 18 of 18 |

5.31r4 and 6.00r2 send 5.30r3's token (`G3D26090`), so the server shapes their
burst as 5.30r3's; they logged in the same way.

The 4.x to 6.x builds log in as to a Login lobby (Seihai notes "nothing but the
level is drawn until it sends a server warp"); the lobby and its warp are stage 6.

The same matrix runs in `cargo test` (`tests/login_matrix.rs`) with Seihai's
client library instead of the binary, 3 s per profile by default; with
`SEIHAI_STAY_SECS=60` all 46 stayed 60 s and got the world-time heartbeat.

## Real clients under Wine

Same day, same build, Wine 9.0 in a network namespace with only `lo`
(`tools/lab-wine.md`). The lab listserver from the handoff folder listed the
server through `tools/lab-register.py`. One client at a time; each walked a
step or two and was left standing.

| client | how it connected | result |
|---|---|---|
| real 1.39 (`GNW07080`, gen 2) | One Player Online, 127.0.0.1:14802 | in game: start board, 3 hearts, 5 bombs, 10 arrows; turned; connected 105 s until stopped |
| real 2.05 rev 2 (`GNW03081`, gen 3) | list on 14921 (shape A), Connect | past the loading screen (the 156 and name-before-board rules hold); walked; 80 s |
| real 2.17.1 (`GNW22122`, gen 3) | list on 14922, "Classic" tab | in game; walked right and down with no "Invalid PlayerProp" (the gen-3 bytes stayed in step with the language in the login frame); 79 s |
| real 2.22 (`GNW03014`, gen 5) | list on 14922, "Bronze" tab | in game; walked; 78 s |
| real 2.31 (`GNW28015`, gen 5) | list on 14922, "Hosted" tab | in game; walked; 86 s |

The server ran with `--verbose`, which logs the first message of each id it does
not handle: none came. Before this branch none of these could log in (the
scaffold exited at start).

Artifacts (project files, `seihai-gserver-lab/stage1-2026-10-31/`): the
server and listserver logs, `lab.pcap` (all five sessions), one in-game
screenshot per client, and both 46-profile matrix logs.
