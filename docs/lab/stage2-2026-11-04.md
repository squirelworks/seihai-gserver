# Stage 2 lab run with real clients, 2026-11-04

Real Graal clients under Wine played the stage 2 world: levels, a link, a gmap,
chests, other players and the anti-cheat. Everything ran in a network namespace
whose only interface is loopback (`tools/lab-wine.md`). No public server and no
real player account were used.

## Setup

- Server: `main` at `733807a` (stage 2.9 merged), `cargo build --release`, run
  with `--verbose`. The world had `create_accounts = true`, `allowedversions.txt`
  = `*`, and the default anti-cheat policy (speed = log, teleport, warp and
  rate = correct).
- Levels, all made for the lab:
  - `onlinestartlocal.nw`: a plain board, `LINK labhouse.nw 30 0 2 1 30 60`,
    a red rupee chest at (24, 26) and a bombs chest at (36, 26).
  - `labhouse.nw`: `LINK onlinestartlocal.nw 30 63 2 1 30 2`, a heart chest
    at (30, 50).
  - `lab_east.nw`: a green rupee chest at (10, 30).
  - `world.gmap`: 2 by 1, `onlinestartlocal.nw` then `lab_east.nw`.
- Lab listserver and `tools/lab-register.py` for the list. 1.39 connected
  directly ("One Player Online", 127.0.0.1, port 14802).
- A small observer built on Seihai's client library logged in as a 2.22 for a
  second at a time and printed each player's level and position.

handled is 38, which each 2.x build sent once.

## Anti-cheat

The anti-cheat logged nothing for 2.22, 2.31, 2.17.1 or 1.39.

It logged five `teleport` lines for 2.05, all for one walk. 2.05 walked past the
top edge of the start level at x 33, where there is no link. That client writes
y = -0.5 as the classic Y byte 0x1F, and the server read the byte as 127.5
tiles. The player was put back each time.
`claude/classic-edge` (PR #33) reads a byte under 0x20 as negative. With that
build, the same walk logged nothing.

The stress rig, at 92 bots and 20 2.05-style clients, had already shown no
false hits, no lost warps and no added latency on the same code. The rig does
not step off a level edge, so it did not catch this.

## Findings

- **Stopping the server loses unsaved progress.** On Ctrl-C the server exits
  without saving the players still online. One 2.05 session in this run lost
  its red rupee chest and 30 rupees this way. The logout save works; a stop
  needs the same save for everyone online.
- On a client's first login, before it has `world.gmap`, 2.22 and 2.31 did not
  draw the chests in the start level, and the first 2.31 login drew no other
  players. On the next login, with the gmap cached, both were drawn. To check:
  whether the burst should send the chests again after the gmap arrives.
- A chest opened in the east gmap cell stayed drawn closed until the next
  login. Seen later from across the seam, it was drawn open.
- 1.39 needs `nodirectinput=true` in `graalconfig.txt` under Wine, or it gets
  no keys. (In stage 1 it only turned.)
- The Reborn clients add to the remembered account name in the login form.
  Clear the field to its end before typing.
