# Stage 6 and the five-client world on real Windows, 2026-11-18 (issues #45, #56)

Real, unchanged Windows clients in a Windows 10 lab VM, against this
server and seihai-listserver on the lab host. Loopback only: the VM's
firewall let it reach nothing but the lab host's lab ports, and the clients'
baked login and list names pointed at the lab host. No public server and no
real account were used. The only client art was Seihai's own server art pack
(seihai#559, `assets/server/`, copied to `<world>/files/server-art/`); no
Graal 2.22 files were in the world.

## Setup

- **Server:** `main` at 0afe61d, then this branch. Run with `--verbose`,
  `allowedversions *`, `create_accounts = true`, `lobby_port` set, and the
  listserver link on.
- **Clients and clock:** the guest clock was held at each build's era:
  2012-11-20 for 6.03r7 (packed Windows exe, token `G3D0311C`), 5.24r4
  (`G3D15010`), 1.39 (`GNW07080`), 2.22 (`GNW03014`) and 2.31
  (`GNW28015`); 2007-07-01 for 4.20r8 (`G3D20126`); 2007-07-25 for 5.00r7
  (`G3D22067`); 2007-11-19 for 5.12 (`G3D14097`).
- **Paths in:** 4.x to 6.x dial their baked Login name on 14900, which
  reached the Login lobby (`lobby_port`). 2.22 and 2.31 used the server
  list. 1.39 used "One Player Online" with the server's address.
- **Level:** an all-grass 64x64 level with one GS1 sign NPC,
  `if (playerenters) { message lab118; }`.

## What was wrong on `main`, and the fixes in this branch

1. **Real Windows 6.03r7 crashed about 13 s after every login.** No window
   ever opened; Windows logged an access violation in `ntdll.dll` (offset
   0x5f603). It happened on the lobby port and on the game port alike, with
   and without level NPCs, the update package or the gani. The same client
   ran on GServer-v2 in the same VM. Leaving `LISTPROCESSES` (182) out of
   the login burst ended the crash, so it is now sent only to builds without
   a Login lobby (the 2.17 to 2.31 builds that answer it). GServer-v2 never
   sends it.
2. **6.03r7 kept a "Connecting to <server>…" box over the level.**
   GServer-v2 sends `ONLINEMODE` (168) after the signature, and
   `SERVERLISTCONNECTED` (190) in the login burst. With both added (190 only
   when `listserver` is set), the box closes as soon as the level is in.
3. **`PLI_VERIFYWANTSEND` (47) went unanswered.** 5.x and 6.x ask for
   `basepackage.gupd` this way on the game server (a GINT5 CRC-32, then the
   name). It is now answered as GServer-v2 does: an update package is always
   sent, a file with the same CRC-32 is "up to date", any other file is
   sent, and a file the world lacks gets no answer.
4. **The lobby warped before the art arrived.** The lobby now answers the
   client's file requests (`WANTFILE`, `UPDATEFILE`, 47) before it sends
   178, until 2 s pass with no request (5 s before the first one, 30 s at
   most). In every run `pics1.png` and the player art were sent before the
   warp: 5 to 11 requests in 2.1 to 2.4 s.
5. **Two 5.x/6.x clients could not be online together.** Both log in as
   `guest`, so the second was refused as "already online". A guest login
   from a lobby build now plays as `pc:<n>`, as on GServer-v2, and is never
   saved.
6. **An NPC with no image (`NPC - x y`) was sent as image `-`.** Every
   build from 1.39 to 6.03r7 then asked for `-.gif`. It is now sent with an
   empty image.
