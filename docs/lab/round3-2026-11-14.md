# Real-client lab, round 3, 2026-11-14: the 1999 rules (#110)

Loopback only, under the same Wine method as before (`tools/lab-wine.md`). No
public server and no real player account were used. Two things differ from
rounds 1 and 2:

- **Host, not VM.** Rounds 1 and 2 ran in the Debian lab VM on Mirae, which
  GwenTea2 cannot reach. This round ran on the GwenTea2 host instead, inside
  a `bwrap --unshare-net` namespace whose only interface is `lo`. That
  namespace held the gserver, the relay, the Xvfb screens and the clients.
  Checked from inside before any client started: 8.8.8.8 gave "Network is
  unreachable", and DNS failed.
- **Name mapping.** Old Graal host names were sent to 127.0.0.1 by
  `hostshim.so` (LD_PRELOAD) instead of a hosts file.

Input went in through XTest (the `gkey` helper). `nodirectinput` was not
needed.

## Setup

- **Server:** branch `claude/project-thread-f7nfab` at `9897e9c`
  (`e4c0ec5` + putnpc / NPC deletion + docs), `cargo build --release`.
  Run with `--verbose` on 127.0.0.1:14812.
- **Relay:** a logging relay on 127.0.0.1:14802 decoded every message
  (gen 2, zlib) with millisecond timestamps (JST). Some 1.x C>S frames did not
  pass the relay's gen-2 unscrambler. Those are logged raw and split into
  messages afterwards; nothing is lost. tcpdump on `lo` ran as well.
- **World:** `r3.nw`, a 64×64 grass board, with:
  - round 2's horse NPC at (40,20): the leader runs `puthorse ride.gif,40,22`
    every 8 s, 12 times;
  - a hare (`BADDY x y 5`, power 1): at 26,34 for the 1999 runs; under `v2`
    it was moved to 14,50, then 20,32, then 32,33 (see check 2).
- **`config/server.txt`:** `respawn_time = 10`, `horse_lifetime = 10`,
  `baddy_respawn_time = 15`, `alignment_time = 30`, `create_accounts = true`,
  `anticheat = off`.
- **Runs:**
  - run A: `rules = 1999`;
  - run A2: `rules = 1999` with `GSERV011` added to `allowedversions.txt`
    (see "Other findings");
  - run B: `rules = v2`, with fresh accounts.

### 1. Kill claims

Both players were at `ALIGN 50` when they logged in. The alignment then rose
one point every 30 s. The victim, c135, logged in at `HP 0.5` next to the
killer, c139. The 1.39 faced it and swung once.

**rules = 1999** (run A):

```
11:23:27.104  S>C 9  40 57          c139 ALIGN 55

11:23:43.045  S>C 9  40 54          to c139: ALIGN 52
11:23:43.045  S>C 8  21 40 54       to c135: player 1 ALIGN 52
```

- The cost was 3, which is round-half-even((51 + 10) / 20).
- The server log has `kill claim: 21`.

**rules = 1999, killer 1.28b2:** the victim c135 was at `ALIGN 63`

### 5. Prop 25 from builds before 1.3

Not reached. What happened:

- **1.28b2 as the killer:** it killed a 1.35 (the claim in check 1 above).
  In its whole session its C>S messages were only:
  - the login props;
  - X/Y/sprite updates (props 15, 16, 17);
  - file requests.

  No prop 25 was sent before or after the kill, so the server never set
  bit 0x20.
- **1.27 as the killer:** it landed one hit on a 1.35 (knock-back, half a
  heart) but no kill. It sent no prop 25 either.
- **Neither 1.28b2 nor 1.27 draws the other players.** Each is sent them:
  for example the 1.28b2 got `S>C 8 26 20 24 c135 ...`, one-byte id. Each is
  also drawn by the 1.35. But neither ever showed another player. So the
  1.28b2's kill was seen only by the victim's client.

  Whether this is the server's `PLO_OTHERPLPROPS` layout for builds before
  1.3 or a limit of these clients is not settled. If the killer's client
  only sets prop 25 when it registers its own hit, this would also explain
  why no prop 25 came.

### 6. `PLI_TOALL`

Typing chat that starts with `toall:` sends message 6. That's Tab, the text,
then Return, on 1.35 and 1.39 alike. The `toall:` prefix is not sent, and
the text goes as a GCHAR length then the text. The server passes it to
everyone else as `PLO_TOALL` (13), with the sender's id first, in each
receiver's id width.

**rules = 1999:**

```
11:29:42.622  C>S 6  27 from135          (1.35)
11:29:42.624  S>C 13 20 24 27 from135    to the 1.39: id 4 as GSHORT
11:29:53.717  C>S 6  27 from139          (1.39)
11:29:53.717  S>C 13 21 27 from139       to the 1.35: id 1, one byte
```

**rules = v2:**

```
11:54:19.922  C>S 6  28 v2from71 -> S>C 13 26 28 v2from71
11:54:23.621  C>S 6  28 v2from72 -> S>C 13 20 27 28 v2from72
```

## Other findings

1. **The 1999 dead-leader hand-off works with real clients.** At
   11:25:22.374 the hare took the leader 1.39 to 0 hearts (`" `, and three
   `PLI_ITEMADD`). At 11:25:23.767 it sent status `28` (0x18, dead). In the
   same millisecond the server sent `PLO_ISLEADER` (10) to the 1.35. From
   then on, the 1.39's baddy changes were not passed on, for example its
   `!$  %#` at 11:25:32.892.

2. **`*` in `allowedversions.txt` leaves out the stand-in builds.**
   - `*` expands to `ClientVersion::all_versions()` (`allow.rs`), not to
     `login::STAND_INS`.
   - So a real 1.27 was refused on a `*` world:
     `c127 [GSERV011 1.21, Gen2]: version not allowed`.
   - The same holds for 1.25 (`GSERV009`), 1.40r1 (`GNW23090`) and the
     2.19–2.21 tokens.
   - Listing `GSERV011` by token let it in. This is a server gap: `*` should
     probably include the stand-ins.

3. **Under v2, a leader that dies and respawns into the same level stops
   running the level.**
   - A 1.x player respawns after death with a `PLI_LEVELWARP` (0) into the
     level it is in.
   - The server answers with the board only (6, 100, 101, 39). It sends no
     NPCs, no baddies and no new `PLO_ISLEADER`.
   - From that moment the 1.39 sent no more baddy AI (15) and no more
     `puthorse` (7), although the server still counts it as the leader. The
     level's baddies froze.
   - Seen three times: deaths at 11:45:27.316, 11:48:10.915 and 11:51:20.806,
     each followed by a warp (2.1 s, 15.7 s and 1.5 s later).
   - The one later `C>S 15` in the third session (11:51:51.780) was the
     1.39's own sword hit on the hare, not its AI.
   - Under 1999 the same client resumed only after it was sent
     `PLO_ISLEADER` again (11:27:14.416, when the 1.35 left).
   - So the server should probably resend `PLO_ISLEADER` (and maybe the
     level's NPCs and baddies) after a same-level warp.
   - This was not changed here.

4. **The v2 hare hunts.** In v2 the hare starts walking (mode 0). It
   hunted and killed a 1.35 logged in at half a heart, 2.7 s after login,
   with no player involved. That is why the v2 kill check needed the hare
   frozen or far away. In 1999 it starts in mode 7 and hops in place
   (26,34 → 26,30–38).
