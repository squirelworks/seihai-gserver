# NPC Control logins, 2026-11-12 (issue #52)

seihai-rc's NC client and a real NPC Control ("GServer2 NPC Control
2001/07/13", token `NCL15031`) logged in to seihai-gserver, with the
NPC-server linked, on loopback. Both list the NPCs. The real NC showed
that scripts and attributes must be tokenized lines. The run was inside a
network namespace with only `lo`, and the real NC ran under 32-bit Wine.
No public server and no real player account were used.

## Setup

- Server: this PR at 43a431a, with seihai-npcserver at 29b2591 and
  `npcserver = auto`, plus a staff account.
- Two NPCs:
  - `bell.txt`: LEVEL/X/Y/IMAGE/SCRIPT format, with a 6-line script.
  - `npcControl.txt`: `GRNPC001` format, type `CONTROL`, no level, with a
    4-line script.

## seihai-rc (`NCL11012`)

| Step | Result |
|---|---|
| NPC list | pass |
| Attributes | pass |
| Script of both NPCs | pass; multi-line scripts exact (raw blocks) |
| Script set, one line | pass; file rewritten and read back |
| Delete `bell` | pass |
| Delete the level-less `Control` | **fail**: file put aside, but no 159, and it stayed listed |
| RC 94 (where is the NPC-server) | not sent: seihai-rc only asks for a listed player named `(Server)`, and this server lists none |

## Real NPC Control 2001 (`NCL15031`)

| Step | Result |
|---|---|
| Login and NPC list | pass: `bell / lab45.nw / 1`, `Control / CONTROL / 2` |
| View Attributes | **fail**: only `name=bell` shown |
| Edit Script | **fail**: the first line, one word per line, comma dropped |
| Send script | **fail**: 109 is the GINT3 id, then the lines tokenized (`"// two words","message hello, world",oneword`). The server wrote that into the file as-is, and the NPC-server refused it |
| Send again after a set | **fail**: the set sent 159 and then 158 for the NPC (the level restart), and the next send carried a garbage id |
| Weapons | 115, answered with an empty 167; the window opens |

This NC does not read raw blocks. It reads 157 and 160 as a tokenized
line list, the same form as an RC's server options (76).

## Fixed after the run

- 157 and 160 carry tokenized lines, and 109 is detokenized (`nc.rs`).
- The NPC-server confirms a delete with `NC_NPC_DELETE` (0x84). Only
  that takes an NPC off the NC lists, so a level-less NPC goes, and a
  script set no longer removes and re-adds the NPC (`npclink.rs`,
  `PROTOCOL.md`).

## Still open
