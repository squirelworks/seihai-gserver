# Real-client lab, round 2, 2026-11-13: weapon cache (#120), 1999 rules (#110), board changes (#107)

Loopback only. Everything ran in a Debian lab VM, inside a private network
namespace whose only interface is `lo`, with the clients under Wine
(`tools/lab-wine.md`). A logging relay in front of the gserver decoded every
message. No public server and no real player account were used.

## #120: GS2 weapons for 4.20r8 (`PLO_WEAPONHASH` 193, 158, 132)

- **Client:** real 4.20r8 (`G3D20126`, Windows, Wine, libfaketime at
  2007-07-01). It came in through `lobby_port` (178 to the game port).
- **World:** two weapons on the account: `Lantern`
  (`if (weaponfired) { say2 light; }`) and `Beacon`.
- **At `c7c7ef6`:**
  - Login 1 went 33 → 193 → the client's 158 → 132 behind
    `PLO_RAWDATA`. The client wrote
    `weblevels/weapons/Rust%032120%032Lab/Lantern.code`.
  - **Login 2 asked 158 again.** 132 left out the bytecode file's final
    line feed, while 193's CRC was over the whole file.
- **At `5c238c8` (#121, 132 sends the whole file):**
  - Login 1: 132 was 97 bytes for `Lantern` and 90 for `Beacon` (raw counts 98 and 91).
  - **Login 2: 193 only, no 158.** Neither `.code` file was rewritten.
  - After `Beacon`'s script changed, login 3 asked 158 for `Beacon` only.
- **The cached files are stored encoded.** Each was 100 bytes with a 4-byte
  header, so a cache file's own CRC-32 is not the 193 value:
  - `Lantern.code`: 0xb06a660a against 193's 0xc23c1b1b;
  - `Beacon.code`: 0xbaaa27ca against 0x3af6c966.
- **Not shown: the weapon running.** The world had no font or player art.
  A `created` → `setplayerprop #c,lit` test sent no chat prop, and selecting
  and firing `Lantern` could not be done by keys.

## #110: the 1999 rules

**Clients:** real 1.35 (`GNW13040`) and 1.39 (`GNW07080`), "One Player
Online" to the game port, and real 2.22 (`GNW03014`) through the listserver.

**World:** the stock `onlinestartlocal.nw` board. A level NPC lets the
leader run `puthorse ride.gif,40,22` every 8 s, 12 times:

```
if (playerenters) { this.n = 0; timeout = 2; }
if (timeout && isleader && this.n < 12) { puthorse ride.gif,40,22; this.n = this.n + 1; timeout = 8; }
```

Also a hare (`BADDY 34 22 5`).

**Settings:** `respawn_time = 10`, `horse_lifetime = 10`,
`baddy_respawn_time = 15`, `alignment_time = 30`.

| Check | rules = v2 | rules = 1999 |
|---|---|---|
| A horse a player leaves is kept, then gone after `horse_lifetime` | **pass** (1.39 got off at x 61.5; `PLO_HORSEDEL` 10.04 s later; round 1) | **pass**: `PLO_HORSEDEL` 10.0 s after the last `PLI_HORSEADD` (13:51:00.967 → 13:51:10.968), to both players |
| A later arrival is sent the horse | not run | **pass**: 1.39 arrived 3.4 s after the leader's add and got `PLO_HORSEADD` (17) `31 70 4c 23 ride` (40, 22) |
| A cut bush grows back | **pass**: 15.0 s (2.22, round 2's `#107` world) | **pass**: 9.03 s, inside 7.5–12.5 s (2.22; one sample) |
| Deaths saved | **pass** (round 1) | **pass**: `DEATHS 1` for 1.39 |
| Alignment rises and is saved | **pass** (round 1) | **pass**: 1.35 from `ALIGN 50` to `56` over about 3 min |
| `PLI_TOALL` reaches everyone | not run | not run |
| A kill claim from 1.21–1.35 is counted | not reached | not reached: 1.39's swings did not kill the 1.35 |
| A baddy whose leader sent mode 9 comes back | not reached | not reached: the hare was not killed |

**Not run:** 1.28b2 and 1.41r1. No real-client way to send `PLI_TOALL` is
known from the 1.x client files.

**The bush on 1.35:** the stock bush at (30,16) is tiles 2, 3 / 18, 19, as
2.22 draws it. 1.35 drew its bushes in other places in the same board, so
aiming at (30,16) did not reach one. The bush checks above used 2.22.

## #107: what a real client sends (`PLI_BOARDMODIFY`, 1)

**Client and world:** real 2.22 on this server, with no `-gr_movement`
weapon. The level is the stock `onlinestartlocal.nw` board, plus one
PushStone object from the 2.22 package's `tileobjects/objectsStandard.txt`
(`bkbl` / `b0b1` = tiles 1764, 1765 / 1780, 1781) at (33, 19)–(34, 20).
Those tiles were 2047 before.

**Cutting a bush:**
- The player stood at (30, 18.5), facing up, below the stock bush at (30, 16).
- The tiles there before were 2, 3 / 18, 19 (the `Bush` object in `objectsStandard.txt`, `ACAD` / `ASAT`).
- One swing sent:

  ```
  C>S 1   21 3e 30 22 22 25 45 25 46 25 55 25 56
          x 30, y 16, w 2, h 2, tiles 677 678 / 693 694
  ```

- The server grew it back with `PLO_BOARDMODIFY` (7) `27 3e 30 22 22 20 22 20 23 20 32 20 33` (tiles 2, 3 / 18, 19). Under `v2` that came 15.0 s later; under `1999`, 9.03 s later.

**Pushing a stone:** walking into the PushStone for 4 s and then 6 s sent
the `push` gani (prop 10 `push`), but the block did not move and no
`PLI_BOARDMODIFY` came in. Whether this world gives those tiles the push
type was not settled.

**Digging:** not tried; no client item that digs is known in this world.
