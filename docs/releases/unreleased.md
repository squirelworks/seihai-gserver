Notes for the next seihai-gserver release.

## Added

- **3D: parity with the seihai-gserver-v2 3D add-on** (`docs/GRAAL3D.md`), ported from the add-on code the Seihai project wrote there. 2D players in a 3D player's level are shown as `G2DPlayer_<account>` objects with their nickname and chat; each link picks its build's row of seihai-core's `VersionProfile::three_d` and sends the 5.x terrain, water and ground cover only to builds that take them; ghosts wait for `MissionStartPhase1Ack` on every protocol; a Camera control object's two extra sections are read and written; GameObject section 2 is the scale (`object` takes `<sx> <sy> <sz>`); events of 16384 bits or more are refused; 3D chat reaches the TCP chat prop. Files the start-up check finds would crash a client are answered as missing; `heights.info` names with spaces or commas, a `heights.info` outside the terrain folder and a second `terrain` line are reported. `weapon3d <name>` without a file sends the server weapon's clientside part, and CRs are stripped. New options: `graal3d_pushterrain`, and for labs `graal3d_terrainall`, `graal3d_trace`, `graal3d_route = sharp3d`, `graal3d_mutate`, plus `rawobject`/`rawevent` world lines. Seihai-core is pinned a second time, by commit, as `seihai-core-3d` for `three_d` until a tagged release carries it. Loopback tests only.

- **3D: terrain, water and ground cover, and safer worlds** (`docs/GRAAL3D.md`). New world lines for protocols 21 and 24 (4.20r6, 4.20r8, 5.x): `terrain` streams a 256 x 256 terrain as a `TerrainBlock` and chunk events and answers the client's chunk stamps with only the chunks that changed; `water` ghosts a `WaterBlock`; `replicator` ghosts ground cover. A start-up check looks up every file the world names and checks `.3ds`, `.dts` and PNG files for the faults that crashed real clients; `graal3d_shapecheck = skip` (default), `warn` or `off` says what a bad shape does. Later players start on rings around the spawn point; after a `g3dpos` move the client's stale reports are set aside until it reports elsewhere; a 3D player's TCP position follows its object, so 2D players and serverside scripts see it move; a leave logs how many clients the object was deleted on. Image requests from 3D clients also find the same stem with another image extension (3.153 asks for `.gif`). Layouts and crash cases from Graal_analysis `torque/terrain-512.md`, `torque/replicators-512.md` and `torque/3d-fuzz-content-512-2026-11-25.md`; loopback tests only, no real-client run from this server yet.

- Apply the existing RC sword/shield image cap to Latin-1 bytes instead of slicing UTF-8 account strings. Mixed Latin-1 names no longer panic or lose bytes prematurely; the server's existing 60-byte cap, power/discriminator and unsupported-character replacement remain unchanged. Accepted-account replies are checked with the pinned peer readers.

- Refuse unsupported RC large-upload transactions without writing their chunks over existing files. Per-session name-only discard state lasts until the matching original end or disconnect; nested starts and wrong ends cannot release it. The matching end returns one browser refusal, then ordinary uploads resume. This is project recovery policy, not large-file support; existing ordinary-upload limits and file rights remain unchanged.

- Decode RC file moves in the pinned peer's documented order: destination-folder GSTRING, then the exact filename. Real pinned-encoder/browser regressions cover moves, root targets, names with spaces and retained rights/path/no-overwrite rules.

- Repeated ordinary player props now keep their final value when a later field restores the previously stored value; no stale intermediate value is retained or sent. Seeded model and receiver-session regressions cover net no-ops, unrelated changes and distinct final values; specialised colour/bow/position paths are unchanged.

- Filter each repeated chat property independently: later matches are filtered and later benign or differently matched text keeps its own result. Real-file/production-model regressions preserve other fields, parser-stop tails and both bow/gani property grammars.

- File requests recover missing/non-file cached paths through the existing rescan interval after assets move or are replaced. Valid cached hits and scanner/name behavior are retained; real-file offer/client readback regressions cover recovery and throttling.

- Reconcile the plan, roadmap and parity notes with merged persistence, NPC-action and account-listing work, retaining unresolved native/lab/release criteria.

- Account listings now omit directories named like account files, including in unconditioned RC replies. Existing account-name filtering and symlink-to-file following are unchanged; real-file/reopen and RC-reply tests cover the fix.

- Deliver representable server-side NPC trigger actions to same-level clients that read packet 48, with server-origin fields and no NPC echo. Refuse unsupported coordinates/text and actions outside the common client transport envelope before enqueueing.

- NPC Control class/weapon deletion now retains the live entry and refuses a success acknowledgment when deleting its backing file fails. Retry uses the original loaded path; class saves also preserve a loaded filename's extension case.

- **The Torque 3D mode** (`graal3d = true`, `docs/GRAAL3D.md`): the UDP link of 3.153 to 6.x clients, protocols 19, 21 and 24, tied to the TCP login by account and IP. Handshake, ghosts (GameObject, Sun, Sky, Camera, TGE Player), datablocks, mission start, protocol 19 moves, and the text channel. Checked against recorded 5.12 packets, a loopback test, and a lab run: a real 4.04r2 (Linux) reaches its control object; a real 5.12 (Windows 10) draws the 3D view once every protocol 21/24 client gets a Camera of its own, which it now does by default (the "Starting 3D mode..." box was a Wine leftover).
- Distinct `LocalPos` / `GlobalPos` types for warp and movement math: wire arrivals (links, RC/NPC warps, login, `PLAYERWARP` / `PLAYERWARP2`) stay level-local; anti-cheat walk and hurt range use gmap-global (`cell * 64 + local`). Regression tests cover warps onto a non-zero gmap cell, between adjacent gmap levels, and from a plain level onto a gmap.
- A client's trigger action (`PLI_TRIGGERACTION`, 38) goes to the other players who read 48, with the sender's id first, and to the NPC-server as `TRIGGER_ACTION` (the action name, the level, and the half-tile point). A new non-empty chat line goes to the NPC-server as `PM_TO_NPC`.
- Stand-ins until `seihai-core` has profiles for them: 1.25 (`GSERV009`) and 1.27 (`GSERV011`) are served as 1.21, 1.40 rev 1 (`GNW23090`) as 1.41 rev 1, and 2.19, 2.2 and 2.21 (`GNW15053`, `GNW28063`, `GNW01113`, type 4) as 2.17.1.
- Every game token in seihai-core's catalogue is now served or named as not served (`login::NOT_SERVED`, with a reason). 23 more stand-ins, each as the nearest build with a profile: 1.33 rev?, 1.34 rev 1, 1.38 rev 1, 1.391, 2.15.1, 2.18, 3.0beta, 3.01, 3.151 Linux (`G3D27015`, which `*` turned away), 4.02.11 to 4.04r2 Linux, 4.10r2/4.11, the real 4.20r6 Mac and 4.20 Linux, the 6.00 betas, 6.015 Mac, 6.01r1 Linux and 6.1.1.3's `GNP1905C` (as 6.03r7). Not served: the unidentified GSERV-era tokens, the later NewWorld token (`G2N29070`), the iPhone builds and the Worlds connector constants. A test fails when a catalogued game token is neither.
- Built on seihai-core v0.7.0. The NewWorld betas (`G2N15041`) are served as NewWorld beta 1, their own profile (beta 2 sends the same token and gets beta 1's message set). Their 8-byte COLORS (core v0.7.1; v0.7.0 said 7, which the 2026-11-19 lab showed wrong) is kept as the usual 5 plus the beta's own last three (pullover, pants, border), which go to the other betas as chosen; a player who sent only five gets the last three filled from the five (see Fixed). Every other build still gets 5. `login::NOT_SERVED` is now seihai-core's list, and a test checks `login::STAND_INS` against core's.
- **2.19 to 2.21 on an INVENTED gen-4 link.** No 2.19 to 2.21 binary survives and no type-4 login has been captured. graal-client-repro's inferred 2.19, 2.2 and 2.21 clients use the type-4 framing this server serves (bzip2 bodies, the gen-5 XOR at its bz2 limit, no compression byte) as an invented link, made up to work rather than observed. A real capture (3.0beta or 3.01, also type 4) would replace it.

## Fixed

- **3D: a file cut over several TCP frames is no longer read as flags.** The flag mirror for 3D links read each frame on its own, so a file over 32000 bytes (a pushed terrain PNG) had its bytes read as messages: garbage went to the 5.12 as flag texts (a garbled message box) and a line starting with a newline panicked. The bytes still to skip now carry over to the next frame. `g3dpos` triggers with quoted fields are read too.
- **3D: an empty line in a TCP frame no longer kills the player's session.** The flag mirror for 3D links sliced past the end of a frame line that started with a newline and panicked, which ended the TCP session and so the 3D link, on the first flag frame of every 3D session (lab, 2026-11-25, real 5.12 against #206).

- Repeated player colours and legacy bow updates now drop any intermediate change when the final normalized value restores the stored one. NewWorld colour tails and legacy bow encoding are preserved.

- **`import-v2` keeps 6.03r7 and the weapons.** GServer-v2's range `G3D11125:G3D0511C` was refused whole, because its first end (4.03r1 Linux) has no profile, so the imported world turned 6.03r7 away until `allowedversions.txt` was edited. A range end served as a near build now stands at its stand-in's place, and stand-in tokens inside a range are allowed. The import now also carries `weapons/*.txt` weapon files and the accounts' `WEAPON` lines, which it used to drop. Found in the graal-client-repro #373 end-to-end lab (2026-11-20: rebuilt 6.03r7 Linux against a world imported from the GServer-v2 fork).

- **A 3D server is listed at HQ level 4.** With `graal3d = true` the server now sends `SERVERHQLEVEL` (24) = 4 after `NEWSERVER`, and the name goes without its own `3 `. Before, it sent no level, so the listserver kept bronze and tagged the name `H `: the list read `H 3 name`, and Mac 3.153, which reads only the first tag, did not see a 3D server (lab finding, 2026-11-20). seihai-listserver already tags level 4 `3 `; seihai-gserver-v2 makes the same change. A 2D server still sends no level.
- **The Mac 4.20r6 (protocol 21) no longer crashes on its first 3D frame.** It reads the scene's Sky and that Sky's seventh texture name without a check, as 3.153 and 4.04r2 do, so it now gets their Skies: every Sky padded to 7 names, and a plain Sky when the world has none. Lab, 2026-11-20 (real Mac 4.20r6 in lab host B's Tiger VM, loopback): before, it linked, finished the mission start and crashed on the first frame with no Sky or a six-name Sky; with this change it activates 3D and the link holds. 5.12 (protocol 24) is unchanged.

- **The lab chat weapon works on 5.x/6.x** (`tools/lab-world`, #174). Its input line never drew on 5.24r4 or 6.03r7: a GS2 `showtext` is a level image placed in tiles, so it now goes to the screen layer with `changeimgvis 200,4`. Backspace cut by the text `strlen(...)-1`; it cuts by a number now. The line opens on Enter with weapons off, so letters no longer fire one, a space is no longer lost, and Escape (the client's quit box on 5.24r4) is not used. Lab, 2026-11-20 (Windows 10 VM, real 5.24r4, 6.03r7, 2.22): the line draws and Backspace works; the narrow chat column from #174 did not reproduce. See `docs/lab/labchat-2026-11-20.md`.
- **The 3D camera now looks at the world.** A protocol 21/24 client's default Camera faces the spawn point instead of looking level along +y, and `camera` in `graal3dworld.txt` takes an optional rotation (`camera <x> <y> <z> [<axis x> <axis y> <axis z> <angle>]`). Angles follow the clients' sense, the opposite of the right-hand rule (lab-checked). `docs/GRAAL3D.md` also notes that a `.3ds` with no material is not drawn at all. Lab, 2026-11-20: a real 5.12 (Windows 10 VM) and a real Linux 4.20r6 (Debian VM) both show the world's cube centred from the default camera.
- **NewWorld beta bodies and colours.** The betas draw a different body sheet (`bodynw.png`, 144 x 2304) and have no `body.png` at all, so the default `body.png` drew as a box. Stock classic bodies (`body`, `body2`, `body3`) now go to a beta as `bodynw.png`, and stock NewWorld bodies (`bodynw`, the race bodies such as `bodyalgo000`) go to every other build as `body.png`. The three extra colour slots (pullover, pants, border) are filled from the classic five (pullover = coat, pants = shoes, black border) instead of colour 0, which drew them white; the betas fill their own the same way. Lab, 2026-11-20 (nwb1, nwb2 and 2.05 rev2 under Wine in lab host A's Debian VM): nwb1 draws its own and the others' bodies, the HUD clock keeps ticking and later players appear. nwb2 and 2.05 draw no bodies under Wine at all, as before.
- **A NewWorld beta's own pullover, pants and border reach the other betas.** The server cut the betas' 8 colours to 5 on the way in, so other betas saw the slots filled from the coat and shoes, not the ones the player chose. The last three are now kept with the player (and in the account, see below) and go to the betas as sent; every other build still gets the first five. Lab, 2026-11-20 (lab host A's Debian VM, Wine, loopback): nwb2 set a red pullover and blue pants, and nwb1 drew them on nwb2's player (all coat-green before).
- **NewWorld betas get served files, so the sword NPC works.** Both betas took a file only with the GINT5 mod time, as 2.05 rev 2 does, and the server sent them none. They dropped every served file, so an NPC whose image the world serves (the lab sword NPC's `block.png`) had no size, was walked through and never ran its `toweapons`. Files now go to both betas with the mod time, which seihai-core v0.7.2 now says for 2.05 and both betas, so the server's own overrides are gone. Lab, 2026-11-20: nwb1 and nwb2 draw `block.png`, it blocks them, touching it sends `PLI_WEAPONADD` and the sword fills S and D; after a re-login the sword is back at once. 2.05 rev 2 is unchanged (saves the file, gets the sword).
- **NewWorld betas get low-depth PNGs as 8-bit.** The betas draw a 1, 2 or 4-bit PNG garbled on a black square (the stock `head0.png` is 4-bit with a palette); every PNG they ship is 8-bit. A palette or grey PNG under 8 bits now goes to them widened to 8 bits per pixel, with the same palette and transparency (`png.rs`); every other build gets the file's own bytes.
- **A NewWorld beta's 8 colours last past the session.** The account now saves COLORS on leave: the classic five for every build, and the beta's own pullover, pants and border as values 6 to 8 on the same `COLORS` line. The next login sends them back to the beta and puts them in the world for the other betas. Five colours from anyone else (a classic client on the same account, an RC) keep the three; only a beta changes them.
- Built on seihai-core v0.7.2, with seihai-npcserver and seihai-rc repinned to it together (one core in the lock file).
- A refused `PLI_WEAPONADD` is now logged with the reason (no such NPC in the level, no script, no `toweapons`, not a default weapon), and `--verbose` logs every weapon ask (33 and 25) with its bytes.
